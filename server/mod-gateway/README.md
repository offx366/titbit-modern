# Закрытая выдача модов

Worker использует **приватный R2-бакет** `BUCKET`. Публичного `r2.dev`, листинга файлов и маршрута чтения произвольного ключа нет. API доступен лаунчерам без аккаунта ChatGPT; скачивание требует ответа на проверку и одноразового токена. Старый открытый пакет GitHub удалён.

## Протокол v1

1. Клиент проверяет SHA256 всех 19 оригинальных файлов. Для диска / ISO используется существующий импортёр: файлы извлекаются локально и проверяются, образ не изменяется.
2. `POST /v1/challenge`, JSON `{ "mod": "widescreen", "version": "0.1.0" }` возвращает 256-битные случайные `id` и `nonce`, срок 180 секунд и 34 диапазона: 16 в QUEST.ezd и по одному в каждом AVI. Диапазоны выбираются заново, размер каждого — 4096 байт.
3. Клиент вычисляет SHA256 доменного префикса, id, nonce, SHA пакета, описаний диапазонов и **самих байтов** этих диапазонов. Один известный публичный SHA файла недостаточен. Функции `proofDigest` / `proof_digest` определяют точную сериализацию. Файлы пользователя на сервер не загружаются.
4. `POST /v1/prove`, JSON `{ "id": "…", "proof": "…" }`. Один запрос допускает одну попытку. Сервер сравнивает ответ с расчётом по закрытой эталонной копии.
5. Правильный ответ выдаёт случайный токен на 120 секунд. `GET /v1/download` принимает его только в `Authorization: Bearer …`. Токены в URL, Range и редиректы запрещены. Начавшееся скачивание может продолжаться после истечения срока токена; повторный старт требует новой проверки.
6. R2 `If-None-Match: *` атомарно фиксирует использование запроса и токена. Параллельные обращения имеют одного победителя. Ответы имеют `Cache-Control: private, no-store`. Пакет проверяется клиентом по закреплённым размеру и SHA256 перед атомарной установкой.

Не более 8 проверок в минуту на сетевой адрес. Запрос и токен связаны с тем же адресом; при смене сети повторите проверку. Адреса хранятся только как хеш с серверным секретом, для краткоживущих ограничений и привязки. Идентификаторов компьютера и регистраций нет. Учёт истечения проверяется при каждом запросе, независимо от удаления записей из хранилища.

## Сервер и обслуживание

Секрет **`GATE_ADMIN_TOKEN`** хранится в runtime secrets Sites. Он не входит в исходники, конфиг лаунчера или исполняемые файлы. Серверу нужна закрытая эталонная копия тех же 19 файлов; она загружается владельцем отдельно от исходников и никогда не выдаётся по API.

Подготовка зарегистрированного Sites checkout с `.openai/hosting.json` (`r2: "BUCKET"`):

```sh
python tools/prepare_mod_gate.py build/private-mod-gateway
cd build/private-mod-gateway
node scripts/build.mjs
node scripts/validate-artifact.mjs
```

Публикация — штатным Sites source workflow. Артефакт содержит единственный Worker и манифест хостинга, без ассетов. Сначала используйте доступ владельца, загрузите данные и проверьте протокол, затем разрешите обращения лаунчеров к API. Публичная доступность API не означает публичную доступность объектов R2.

Начальное заполнение приватного бакета:

```sh
python tools/seed_mod_gate.py --origin https://YOUR-SITE --data /path/to/original-game --package /path/to/mod.titbitmod
```

CLI принимает JSON с `admin` и, для приватного Site, `service` через скрытый stdin; не передавайте ключи аргументами командной строки или файлами. Загрузка порциями по 8 МиБ, затем потоковая сборка с проверкой полного SHA256 на стороне R2. Уже проверенные объекты повторно не загружаются. Административные запросы без секрета получают 404. `POST /admin/cleanup` удаляет ограниченную порцию истёкших временных записей; фоновая уборка также запускается на части запросов проверки. Рабочие reference/mod объекты уборкой не затрагиваются.

## Проверка

```sh
node --test server/mod-gateway/gateway.test.mjs
python -m unittest tools/tests/test_titbit_gate.py tools/tests/test_titbit_mods.py
```

Проверяются прямой доступ, неверные/повторные/просроченные ответы, повтор токена, гонки двух запросов, ограничение частоты и недопустимые диапазоны на клиенте. Реальные облачные проверки сохраняются локально в `build/private-gate-qa/`, без секретов и токенов.

Это подтверждение доступа к данным поддерживаемой версии игры, а не покупки или лицензии. Уже полученные файлы пользователь технически может скопировать; протокол не заявляет защиту от дальнейшей раздачи.
