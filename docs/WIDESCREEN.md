# Экспериментальный widescreen

Ветка `widescreen-outpaint`. Изменения не объединяются с `main`.
Оригинальный `QUEST.ezd` читается без записи. Новые изображения, моды и игровые
снимки находятся в игнорируемом каталоге `build/widescreen/`.

## Изображения и геометрия

Задник перегенерируется **целиком**, без вклейки исходного центра.
Цель генерации — сохранить стиль, перспективу и расположение объектов.
Движок сохраняет вертикальный угол обзора.
Генератор может изменить геометрию изображения, поэтому проверка совмещения
с персонажами, анимацией и перекрывающими объектами обязательна.

В исследованном архиве: 70 сцен, 40 задников игровых локаций и один задник
мини-игры. Картинка локации занимает **нижние 768 строк** декодированной
текстуры 1024×1024; верхние 256 строк могут содержать отдельные детали атласа.
Оригинальные атласы сохраняются целиком. Новая текстура имеет размер
2048×1024 и собственный материал, используемый только плоскостью фона.
Конвейер расширяет эту плоскость и пересчитывает её U-координаты.
Остальные 3D-предметы сохраняют исходные текстуры и маски прозрачности.
Альфа-маска фонового слоя также сохраняется: это не вклейка старого RGB.
Например, у ворот облака — фон, а створки и компьютер — отдельные 3D-объекты;
их нельзя повторно рисовать в непрозрачном заднике.

Варианты: 1366×768 и 1230×768. Второй — центральный срез того же нового кадра;
чётная ширина оставляет симметричные поля вокруг игрового интерфейса.

## Конвейер

Нужны Python 3.11+ и Pillow из основных зависимостей проекта.
Из корня репозитория:

```sh
python tools/widescreen.py run --archive /path/to/game/QUEST.ezd
```

Первый запуск создаёт `manifest.json`, `generation-jobs.json`, исходные PNG,
промпты и контактные листы. Если изображений нет, команда завершится с кодом 3
и списком ожидаемых файлов. Она не подставляет растянутые края или заглушки.

Рядом с исходниками автоматически сохраняются `atlas-alpha-mask.png` и
`background-uv-mask.png` — маски из альфа-канала и треугольников модели.
`side-regions-mask.png` обозначает боковые области как ориентир;
`generation-mask.png` оставляет весь кадр доступным для перерисовки.
Это не маски коллизий и не запрет менять центр.

Генерация изображений — отдельный этап: встроенный `image_gen` вызывается из
Codex, Python-скрипт не имеет к нему прямого доступа. Результат каждого задания
сохраняется как `build/widescreen/incoming/<id>.png`. Готовый широкий кадр
масштабируется до рабочего разрешения; оригинальные пиксели поверх него
**не накладываются**. Промпт и происхождение сохраняются рядом с результатами.

Повтор той же команды принимает новые изображения и собирает оба отдельных
архива в `build/widescreen/mod/16x9/` и `mod/16x10/`. Рабочие игровые каталоги
`runtime/` получают копии исходных AVI, собственные настройки и сохранения.
`--partial` разрешает промежуточную сборку: неподготовленные сцены остаются 4:3.

Явно согласованные исключения перечисляются по одному имени XML в
`build/widescreen/original-scenes.txt`. Они остаются с оригинальными фонами
и не учитываются среди ожидающих генерации. Для общего задника нужно указать
все его сцены; неизвестные имена отклоняются. В этой локальной сборке это
только `sex_podval.XML`, `sex_podval_n.xml`, `sex_podval_divan.XML`.

Полный повтор сборки и проверки подготовленных изображений одной командой:

```sh
python tools/widescreen.py run --archive /path/to/game/QUEST.ezd \
  --linux-exe build/widescreen/linux/titbit
```

В Windows используется WSL `Ubuntu-24.04`; в Linux — локальный Xvfb.
Нужны зависимости существующего `linux-port/tools/headless_probe.py`.
Конвейер не запускает игру на видимом рабочем столе.

Для повторной правки стойки дискотеки сохранены
[промпты и порядок подготовки маски](../tools/widescreen-prompts.json).
Контур служит ориентиром для генерации; исходный RGB поверх результата
не накладывается.

### Совмещение с оригинальными объектами

После генерации нужно сверять положение дверей, лестниц, мебели и горизонта
с исходной камерой. `accept --align` выполняет регистрацию SIFT/RANSAC
(опционально нужен `opencv-python`). Это геометрическая проверка,
а не автоматическое одобрение картинки. Если преобразование оставило пустые
края, их нужно дорисовать через генератор и проверить до упаковки.

Для уже совмещённого кадра:

```sh
python tools/widescreen.py accept <id> <frame.png> --source-aligned
```

В подъезде два оригинальных спрайта плакатов содержат непрозрачную рамку
старой стены. Для совмещённых задников упаковщик разделяет их плоскости:
бумага сохраняет оригинальный материал, окружающее кольцо берёт цвет нового
задника по проекции исходной камеры. Контур, глубина и взаимодействия объекта
сохраняются. Исправление ограничено двумя известными моделями с проверкой
хешей; текстуры оригинала не переписываются.

Для крупного плана дискотеки нужен фон **без стойки и её подиума**:

```sh
python tools/widescreen.py accept club_dans_render_02.tga <clean-plate.png> --native-foreground
```

Стойку рисует родная модель с исходными RGB и альфа-каналом. Упаковщик
добавляет недостающие треугольники по её реальному контуру; иначе край подиума
обрезается. Этот флаг разрешён только для зарегистрированного задника дискотеки.

Чтобы обычная команда `run` воспроизводила эти настройки, рядом с входным
PNG сохраните JSON с тем же именем. Для совмещённого кадра:

```json
{"sourceAlignedSceneArt": true, "nativeForeground": false}
```

Для фона дискотеки без стойки: `{"nativeForeground": true}`.
Промпты, маски и матрицы регистрации можно хранить в этом же JSON;
картинки и все результаты остаются в игнорируемом `build/`.

## Движок

Сборка Windows — существующей командой проекта с отдельным выходным каталогом:

```powershell
python tools/build_modern.py --out build/widescreen/windows
```

Настройки рядом с EXE:

```ini
[compat]
display=windowed
resolution=1366x768
aspect=widescreen
widescreen_ratio=16:9
```

Для 16:10: `resolution=1230x768`, `widescreen_ratio=16:10`.
`widescreen-scenes.txt` из соответствующего мода кладётся рядом с EXE.
Путь можно переопределить переменной `TITBIT_WIDESCREEN_SCENES`.

Сборка Linux:

```sh
python3 linux-port/tools/build_linux.py --build-dir build/widescreen/linux
```

Параметры игры: `--data <runtime-каталог> --widescreen=16:9` или
`--widescreen=16:10`. Список подготовленных сцен читается из каталога данных.
В текущем эксперименте игровые запуски выполняются только через скрытый
Windows desktop либо `headless_probe.py`/Xvfb.

Без опции сохраняется 4:3. Меню, диалоги и мини-игры остаются
в центральной области; горизонтальный обзор расширяется только для сцен из
списка. Сам список не заменяет архив с новой геометрией и изображениями.

Инвентарь закреплён у левого края широкого окна. Отрисовка, проверка наведения
и координаты скриптов используют одно преобразование; исходная анимация панели
и расположение ячеек сохранены. Переносимый предмет следует за курсором по всей
ширине. В Linux указатель в боковой полосе центрального меню не превращается
в нажатие на его крайнюю кнопку. При переходе между широким и центральным
кадром очищаются обе боковые области.

Некоторые предметы оригинала — непрозрачные плоские изображения вместе с
прямоугольным фрагментом старой стены или пола. `widescreen_native_contours.json`
отделяет их силуэты от окружения: RGB предмета сохраняется, окружение берётся
из нового задника через исходную камеру. Для листвы и велосипеда маска
вычисляется из пользовательской текстуры (`widescreen_native_masks.py`).
Материалы и текстуры клонируются внутри мода, оригинальный архив не меняется.
Полезная геометрия перекрытий сохраняется. Вывеска у входа в «Сумерки
человечества» сохраняет оригинальный случайный таймер: буквы «МЕР» гаснут,
оставляя «СУКИ человечества». Обе фазы используют новый задник с одинаковой
привязкой к камере; прямоугольник исходной стены не возвращается.

`widescreen_exits.py` переносит невидимые зоны боковых переходов к новым
границам кадра и расширяет нижние зоны на добавленную ширину. Форма зоны по
вертикали, скрипт перехода, курсор-нога и анимация ходьбы сохраняются. Изменяются
только отдельные root-box без видимой геометрии, выровненные по исходной камере
и касающиеся старой границы экрана. Двери и переходы внутри сцены сохраняют
свои координаты. Эти изменения XML находятся только в широком архиве-моде.

Отдельные архитектурные слои облаков и передней скамьи также получают RGB из
нового задника; их исходные альфа-маски и глубина сохраняют перекрытие героя.
Облака читают выделенный атлас напрямую с привязкой к камере: дополнительное
уменьшение изображения не создаёт тонкую линию на прежней границе кадра.
Все кадры лабораторных компьютеров сохраняют оригинальные экраны и корпус,
без прямоугольников старой стены. У трёхмерной барной стойки координаты U>1
ранее находились за кадром и повторяли чужую часть атласа. Изолированная копия
текстуры с продолжением крайнего столбца устраняет повтор; исходные пиксели
стойки и её геометрия не меняются. Это исправление семплирования объекта,
дорисованные задники по-прежнему создаются целиком.

Повторная сборка мода публикует архив атомарно после проверки содержимого.
Уже открытая или связанная жёсткой ссылкой копия остаётся неизменной.

Полноэкранные вспышки и затемнение покрывают весь широкий кадр. Для них
платформенный слой распознаёт плоскость 1024×768 с малым участком текстурного
атласа и временно расширяет viewport. Обычные изображения меню и частичные
панели продолжают рисоваться по центру; скрипты эффектов не меняются.

## Проверка

### Главное меню

Главное меню, настройки и сохранение/загрузка поддерживают отдельный широкий
фон. Полный фон генерируется без текста; надписи извлекаются из пользовательских
ресурсов игры с исходными размерами и координатами. Подсветка использует ту же
форму букв. Дорисовка не растягивает шрифты, ползунок, кнопки или миниатюры.

После получения фонового изображения 16:9 без надписей:

```sh
python tools/widescreen_menu.py --archive /path/to/QUEST.ezd --generated /path/to/menu.png
python tools/widescreen.py pack --ratio 16x9 --require-complete
python tools/widescreen.py pack --ratio 16x10 --require-complete
```

Генерация описана в `tools/widescreen_menu.prompt.txt`. Изображение и его
отпечатки хранятся только в `build/widescreen/menu/`; при отсутствии принятого
изображения сборщик сохраняет исходное меню. Широкий фон требует текущей
сборки движка Windows/Linux; без опции widescreen сохраняется исходное 4:3.
В моде меняются только четыре скрипта создания фона (имена текстур и UV),
исходные обработчики кнопок и координаты нажатий сохраняются.

`build/widescreen/report.md` связывает каждую сцену с кадрами обоих форматов.
Хеши EXE, архива, списка сцен и параметров фиксируются в результатах запуска.
Повторное использование снимков другого мода запрещено.

Короткий direct-scene запуск проверяет загрузку и рендер, но не прохождение
квеста. Состояние сюжета, движение камеры, выходы, анимацию и перекрытия нужно
проверять отдельно; отсутствие проверки явно отмечается в отчёте.
`reviews.json` хранит замечания по сценам. Кадр успешной загрузки не означает
визуального одобрения автоматически.

Тесты преобразования архива, плоскостей, атласов и полной замены изображения:

```sh
python -m unittest discover -s tools -p 'test_widescreen*.py'
```
