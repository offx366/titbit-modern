# Экспериментальный widescreen

Ветка `widescreen-outpaint`. Изменения не объединяются с `main`.
Оригинальный `QUEST.ezd` читается без записи. Новые изображения, моды и игровые
снимки находятся в игнорируемом каталоге `build/widescreen/`.

## Изображения и геометрия

Задник перегенерируется **целиком**, без вклейки исходного центра.
Цель генерации — сохранить стиль, перспективу и расположение объектов.
Движок сохраняет вертикальный угол обзора.
Генератор может изменить геометрию изображения, поэтому проверка совмещения
с персонажами, анимацией и перекрывающими объектами обязательна.

В исследованном архиве: 70 сцен, 40 задников игровых локаций и один задник
мини-игры. Картинка локации занимает **нижние 768 строк** декодированной
текстуры 1024×1024; верхние 256 строк могут содержать отдельные детали атласа.
Оригинальные атласы сохраняются целиком. Новая текстура имеет размер
2048×1024 и собственный материал, используемый только плоскостью фона.
Конвейер расширяет эту плоскость и пересчитывает её U-координаты.
Остальные 3D-предметы сохраняют исходные текстуры и маски прозрачности.
Альфа-маска фонового слоя также сохраняется: это не вклейка старого RGB.
Например, у ворот облака — фон, а створки и компьютер — отдельные 3D-объекты;
их нельзя повторно рисовать в непрозрачном заднике.

Варианты: 1366×768 и 1230×768. Второй — центральный срез того же нового кадра;
чётная ширина оставляет симметричные поля вокруг игрового интерфейса.

## Конвейер

Нужны Python 3.11+ и Pillow из основных зависимостей проекта.
Из корня репозитория:

```sh
python tools/widescreen.py run --archive /path/to/game/QUEST.ezd
```

Первый запуск создаёт `manifest.json`, `generation-jobs.json`, исходные PNG,
промпты и контактные листы. Если изображений нет, команда завершится с кодом 3
и списком ожидаемых файлов. Она не подставляет растянутые края или заглушки.

Рядом с исходниками автоматически сохраняются `atlas-alpha-mask.png` и
`background-uv-mask.png` — маски из альфа-канала и треугольников модели.
`side-regions-mask.png` обозначает боковые области как ориентир;
`generation-mask.png` оставляет весь кадр доступным для перерисовки.
Это не маски коллизий и не запрет менять центр.

Генерация изображений — отдельный этап: встроенный `image_gen` вызывается из
Codex, Python-скрипт не имеет к нему прямого доступа. Результат каждого задания
сохраняется как `build/widescreen/incoming/<id>.png`. Готовый широкий кадр
масштабируется до рабочего разрешения; оригинальные пиксели поверх него
**не накладываются**. Промпт и происхождение сохраняются рядом с результатами.

Повтор той же команды принимает новые изображения и собирает оба отдельных
архива в `build/widescreen/mod/16x9/` и `mod/16x10/`. Рабочие игровые каталоги
`runtime/` получают копии исходных AVI, собственные настройки и сохранения.
`--partial` разрешает промежуточную сборку: неподготовленные сцены остаются 4:3.

Полный повтор сборки и проверки подготовленных изображений одной командой:

```sh
python tools/widescreen.py run --archive /path/to/game/QUEST.ezd \
  --linux-exe build/widescreen/linux/titbit
```

В Windows используется WSL `Ubuntu-24.04`; в Linux — локальный Xvfb.
Нужны зависимости существующего `linux-port/tools/headless_probe.py`.
Конвейер не запускает игру на видимом рабочем столе.

Для повторной правки стойки дискотеки сохранены
[промпты и порядок подготовки маски](../tools/widescreen-prompts.json).
Контур служит ориентиром для генерации; исходный RGB поверх результата
не накладывается.

## Движок

Сборка Windows — существующей командой проекта с отдельным выходным каталогом:

```powershell
python tools/build_modern.py --out build/widescreen/windows
```

Настройки рядом с EXE:

```ini
[compat]
display=windowed
resolution=1366x768
aspect=widescreen
widescreen_ratio=16:9
```

Для 16:10: `resolution=1230x768`, `widescreen_ratio=16:10`.
`widescreen-scenes.txt` из соответствующего мода кладётся рядом с EXE.
Путь можно переопределить переменной `TITBIT_WIDESCREEN_SCENES`.

Сборка Linux:

```sh
python3 linux-port/tools/build_linux.py --build-dir build/widescreen/linux
```

Параметры игры: `--data <runtime-каталог> --widescreen=16:9` или
`--widescreen=16:10`. Список подготовленных сцен читается из каталога данных.
В текущем эксперименте игровые запуски выполняются только через скрытый
Windows desktop либо `headless_probe.py`/Xvfb.

Без опции сохраняется 4:3. Меню, диалоги, интерфейс и мини-игры остаются
в центральной области; горизонтальный обзор расширяется только для сцен из
списка. Сам список не заменяет архив с новой геометрией и изображениями.

Полноэкранные вспышки и затемнение покрывают весь широкий кадр. Для них
платформенный слой распознаёт плоскость 1024×768 с малым участком текстурного
атласа и временно расширяет viewport. Обычные изображения меню и частичные
панели продолжают рисоваться по центру; скрипты эффектов не меняются.

## Проверка

`build/widescreen/report.md` связывает каждую сцену с кадрами обоих форматов.
Хеши EXE, архива, списка сцен и параметров фиксируются в результатах запуска.
Повторное использование снимков другого мода запрещено.

Короткий direct-scene запуск проверяет загрузку и рендер, но не прохождение
квеста. Состояние сюжета, движение камеры, выходы, анимацию и перекрытия нужно
проверять отдельно; отсутствие проверки явно отмечается в отчёте.
`reviews.json` хранит замечания по сценам. Кадр успешной загрузки не означает
визуального одобрения автоматически.

Тесты преобразования архива, плоскостей, атласов и полной замены изображения:

```sh
python -m unittest discover -s tools -p test_widescreen.py
```
